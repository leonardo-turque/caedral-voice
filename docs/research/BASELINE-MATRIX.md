## Phase C shortlist

**Criteria** (per program brief): (a) permissive license on *both* code and weights usable in a commercial product; (b) pip-installable (or single-wheel) without bespoke build systems; (c) demonstrably CPU-runnable today (batch-1 = first-utterance latency matters); (d) architecturally representative so results generalize across classes.

### Recommended baselines to install & benchmark locally on CPU (priority order)

1. **Kokoro-82M (v1.0)** — the anchor. Apache-2.0 code+weights, `pip install kokoro`, ONNX int8 path exists, proven multi-voice English quality at 82M. Represents the modern small-NAR / StyleTTS2-derived class. Every Caedral quality claim should be measured against it.
2. **Piper (piper1-gpl ≥ 1.5.0)** — the incumbent production baseline. Real-time on ARM-class CPUs via ONNX Runtime; huge voice catalog to calibrate WER/RTF harnesses. **Caveat: GPL-3.0 code — benchmark from a separate process/virtualenv; do not link into proprietary code.**
3. **Chatterbox-Nano (110M)** — the frontier probe. MIT, vendor-claimed 3× real-time on an 8-core CPU, zero-shot cloning + paralinguistic tags at exactly Caedral's size class. Represents the 2025–2026 distilled speech-LM trend. Converts [REPORTED] RTF into [REPRODUCED] evidence.
4. **KittenTTS (mini 80M, nano 15M as stretch)** — the floor-setter. Apache-2.0, ONNX-only ≤80 MB models, Windows supported. Defines the minimum viable footprint/quality trade-off. Caveat: developer-preview API; installs via GitHub release wheel, not PyPI.
5. **F5-TTS (v1)** — stretch / quality-ceiling row. MIT *code* (`pip install f5-tts`) but **CC-BY-NC weights**: benchmark for architecture reference (flow-matching class) and cloning quality only — **not shippable**. If flow-matching proves central to Caedral's roadmap, plan self-training under the MIT training code.

### Honorable mentions / conditional
- **NeuTTS Air** (Apache-2.0 Air model, GGUF Q4 ≈527 MB): add only if zero-shot cloning on CPU becomes a hard Phase C requirement; its GGUF toolchain differs from the rest of the batch.
- **MeloTTS** (MIT): redundant with the Piper/Kokoro roles; keep as backup if Piper's GPL blocks a workflow.
- **StyleTTS2**: benchmark only if we plan to *retrain* under its MIT code — official LibriTTS/LJSpeech weights carry non-MIT disclosure/consent terms.

### Windows caveats found during survey
- **espeak-ng external install**: required by several stacks (StyleTTS2 phonemizer path, Matcha-TTS, Zonos, some MeloTTS setups). Piper *embeds* espeak-ng; Kokoro uses the pure-Python Misaki G2P main path. Budget for a silent-installer story in deployment scripts.
- **piper1-gpl**: v1.5.0 (Jul 2026) specifically fixed libpiper builds on Windows (MSVC, MSYS2-GCC) — prefer ≥1.5.0 wheels over source builds.
- **KittenTTS**: no PyPI package as of v0.8.1 — pip-install directly from the GitHub release wheel URL; int8 variant has reported issues.
- **ONNX Runtime is the common denominator** (Piper, KittenTTS, Kokoro ONNX community builds, Matcha export path); standard pip wheel works on Windows x64.
- GPU-only stacks (Dia, IndexTTS, VoxCPM, Fish S1, Orpheus/CSM/Zonos class) are CUDA-first with pinned wheels — skip for the CPU batch.
- F5-TTS Gradio demos and Chatterbox assume Linux dev conventions; expect path/encoding friction scripting batch runs on Windows.
